# SingletonIdGenerator

Консольная программа на C#, которая выдаёт уникальные числовые ID и ID с префиксом (например, `USR-1`, `ORD-2`) через один общий генератор.

## Singleton в этом проекте: где, как и почему

### Где используется Singleton

Singleton реализован в классе `IdGenerator`:

- `private static IdGenerator _instance;` — хранит единственный экземпляр класса.
- `private IdGenerator() { }` — закрывает создание объекта извне (`new IdGenerator()` недоступен).
- `public static IdGenerator GetInstance()` — единственная точка доступа к экземпляру.

Именно через `GetInstance()` весь код получает один и тот же объект генератора.

### Как работает реализация

1. При первом вызове `GetInstance()` проверяется `_instance`.
2. Если экземпляра ещё нет, внутри `lock (_lock)` создаётся `new IdGenerator()`.
3. При следующих вызовах возвращается уже созданный объект.

Дополнительно потокобезопасность самой генерации обеспечивается через:

- `Interlocked.Increment(ref _counter)` — атомарно увеличивает счётчик и возвращает следующее значение.

Это важно, чтобы в многопоточном сценарии не появлялись дубликаты ID.

### Почему здесь выбран Singleton

Для генератора ID в рамках одного процесса обычно нужен **единый источник последовательности**.

Если создать несколько независимых генераторов, у каждого будет свой `_counter`, и можно получить пересечения диапазонов (например, у каждого экземпляра начнётся с `1`). Singleton решает это:

- состояние счётчика централизовано в одном объекте;
- все части программы используют один и тот же источник ID;
- поведение предсказуемо и проще контролируется.

### Почему это подходит именно этому примеру

В `Main` создаются две переменные:

- `generator1 = IdGenerator.GetInstance()` 
- `generator2 = IdGenerator.GetInstance()` 

Проверка `Object.ReferenceEquals(generator1, generator2)` показывает `True`, то есть это одна и та же ссылка на один объект. Поэтому вызовы `NextId()` через обе переменные продолжают одну общую последовательность.
